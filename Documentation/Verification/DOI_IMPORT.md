# DOI imports

Verified on 17 November 2026: all 127 tests passed under Swift Package Manager and Xcode, including the arXiv and DOI URLSession transfer cases. Native Debug and Release builds succeeded. The live upgrade of an existing IEEE record recovered its full abstract and preserved notes, identities and course assignments; the MDPI lookup discovered a public PDF URL. The Release app was packaged at `build/release/Paper Library.app`; the single-app inventory and strict signature verification passed with bundle identifier `local.paperlibrary.app`.

The Add Papers link input accepts mixed arXiv identifiers and DOIs, including bare DOIs, `doi:` prefixes, `doi.org` and `dx.doi.org` URLs, percent-encoded paths and the escaped scheme spelling in the supplied examples. DOI normalization folds case. Batch parsing deduplicates normalized inputs while keeping failed rows visible.

`ImportIdentifier` distinguishes the two providers. Existing job columns store the canonical identifier and optional arXiv version, so the persisted schema and existing library need no migration. Interrupted DOI jobs are recovered through the existing explicit retry flow.

The DOI client requests JSON only from fixed Crossref endpoints, then DataCite when Crossref reports 404. It validates the returned DOI, requires a title, and tolerates missing optional metadata. Ordered authors, publication dates, journal references and abstracts are retained when supplied; metadata markup is converted to plain text. A partial refresh preserves previously retrieved optional fields. The service documentation is available from [Crossref](https://www.crossref.org/documentation/retrieve-metadata/rest-api/) and [DataCite](https://support.datacite.org/docs/rest-api).

The client also looks up the exact DOI in OpenAlex. It validates identity and reconstructs the abstract from a bounded, contiguous inverted index, rejecting conflicting or invalid positions. Existing publisher abstracts take precedence. Only locations explicitly marked open access contribute PDF URLs. An optional enrichment failure preserves the valid base import. See the [OpenAlex work attributes](https://help.openalex.org/data/works/attributes/) and [open access locations](https://help.openalex.org/data/locations/).

Selecting a DOI paper imported before this change queues a refresh through the existing durable import worker. A successful lookup is recorded in the existing metadata status field, avoiding repeated automatic requests. A session also avoids repeating failed automatic attempts. The explicit Refresh Abstract and PDF action permits retry. A retrieved abstract fills an empty abstract while retaining manually edited titles, existing abstracts, notes and course assignments.

Requests use an ephemeral session without cookie storage, credentials or caching. Both advertised and streamed metadata responses are limited to 2 MiB; redirects are rejected. Transient failures have bounded retries and respect Retry-After. The existing import worker serializes DOI requests and isolates failures by job. Network errors never create a paper without valid metadata.

DOI imports reuse existing normalized identities or a paper already carrying the DOI. Importing arXiv metadata can reuse a DOI or manual record, while distinct arXiv identities remain distinct. Notes, favorites, reading state, courses and manually edited metadata retain their existing protection. Refreshing a paper matched by DOI preserves its arXiv or local PDF source identity. Deletion also cancels pending DOI jobs matching the deleted paper.

The detail view always offers publisher PDF access and attachment for DOI papers. Known public MDPI, PubMed Central and PLOS PDF routes can use the existing bounded downloader; other public links open in the browser. Public metadata does not establish that a subscription paper can be downloaded without access. The IEEE example is indexed with an abstract but no public PDF copy, so publisher access and attachment remain available.

The arXiv policy still requires a pinned version and rejects redirects. Publisher downloads accept at most four redirects, each restricted to the supported public PDF routes. Private hosts, credentials, arbitrary query endpoints and HTML responses cannot become installed PDFs. Attachments use the existing validated local-copy flow, target the selected paper explicitly and preserve previous versions. Reattaching the same bytes reuses the existing document; a different copy creates a new document version. Source size checks refresh URL resource values so a replaced local file is validated against its current bytes.

## Verification

- `bash Scripts/verify.sh` runs configuration checks, storage safety checks, Swift package tests, native Xcode tests, and Debug and Release builds in isolated temporary app directories.
- DOI regression tests cover normalization, mixed batches, provider fallback, absent metadata, identity mismatch, retries, network policy, redirects, advertised and streamed response limits, persistence, interruption, cancellation, duplicate handling, protected refreshes, abstract reconstruction and old-record repair. PDF checks cover public DOI routes, streamed transfers, extraction, attachment, duplicate bytes and retained document versions.
- `.build/debug/DOILiveCheck --live` imports both supplied DOI links into a disposable library, then upgrades those records through the production client. It checks recovery of the IEEE abstract, discovery of the MDPI public PDF URL and preserved notes, identities and course assignments. It does not claim an unauthenticated IEEE PDF download.
- `bash Scripts/build-app.sh release` publishes the signed app at the single canonical path. `python3 Scripts/check_single_app.py` and `codesign --verify --deep --strict "build/release/Paper Library.app"` check the final artifact.

The live check never opens the production library or invokes PDFs or AI. Native interface compilation is verified; the DOI entry workflow has not been reviewed through interactive UI automation.
